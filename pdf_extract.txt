1.​ Initialize Project: បង្កើត NestJS / Express TypeScript Project ជាមួយ Folder Structure 
បែប Clean Architecture / Modular Structure (/modules, /common, /config, 
/database)។ 
2.​ Docker Compose Setup: បង្កើត docker-compose.yml រួមមានសេវា PostgreSQL និង

3.​ Environment Management: រៀបចំ .env និង Validation Module (JWT Secret, Database 
URL, Redis Port, AES Encryption Key, Bakong/Payment API Keys)។

3.​ Database Seeding: សរសេរ Script seed.ts ដើម្បីបង្កើតទិន្ន័យគំរូដើម៖

Module) 
1.​ User Registration & Login: អភិវឌ្ឍ API ចុះឈ្មោះ និងចូលប្រើប្រាាស់ ដោយប្រើ bcrypt (Salt 
rounds = 12) សម្រាាប់ Hash លេខសម្ងាត់។ 
2.​ OAuth & Social Authentication: Integrates Google OAuth និង Telegram Login 
ដោយប្រើ HMAC-SHA256 signature verification សម្រាាប់ការផ្ទៀងផ្ទាត់សុវត្ថិភាព ព្រមទាំងអនុវត្ត 
strict constraint ការពារមិនឱ្យមានលេខទូរស័ព្ទស្ទួនគ្នា (no-duplicate phone number 
constraint)។ 
3.​ Password Reset Flow: អភិវឌ្ឍប្រព័ន្ធផ្លាស់ប្តូរលេខសម្ងាត់តាមរយៈ single-use hashed token 
ដែលមានសុពលភាព 15 នាទី និងធ្វើការលុបចោលរាល់ active refresh tokens (auto-revocation) 
ដោយស្វ័យប្រវត្តិពេលផ្លាស់ប្តូរជោគជ័យ។ 
4.​ JWT Dual-Token Strategy: 
○​ Access Token: មានសុពលភាពខ្លី (15 នាទី) សម្រាាប់ផ្ញើជាមួយ Header ពេលហៅ APIs។ 
○​ Refresh Token: មានសុពលភាពវែង (7 ថ្ងៃ) រក្សាទុកក្នុង HttpOnly Cookie ឬ Redis 
Session Store Store។ 
5.​ Role-Based Access Control (RBAC): បង្កើត Middleware/Guards ដើម្បីការពារ Route តាម 
Role នីមួយៗ (buyer, seller, admin)។ 
ជំហានទី ៤៖ សេវាគ្រប់គ្រងទំនិញ និងព័ត៌មានសម្ងាត់ (Listing & Credential Vault 
Module) 
1.​ Game & Category API: API ទាញយកបញ្ជីហ្គេម និង Rank/Categories បម្រើឱ្យ Dropdown 
Filter លើប្រព័ន្ធ។ 
2.​ Account Listing API: 
○​ CRUD Listing សម្រាាប់ User និង Admin (សម្គាល់ is_platform_owned = 
true/false)។ 
○​ Dynamic Filtering, Full-text search និង Pagination (page, limit, sort, rank, 
priceRange)។

3.​ Cryptographic Credential Service (AES-256-GCM): 
○​ បង្កើត CryptoService សម្រាាប់ Encrypt login_identifier, 
login_password, និង backup_codes មុននឹង Save ចូល Database Vault Table។ 
○​ Method Decrypt ត្រូវបានអនុញ្ញាតឱ្យហៅបាន តែពេល Order 
ត្រូវបានបង់ប្រាាក់ជោគជ័យប៉ុណ្ណោះ។ 
○​ Game Binds Verification & Snapshot: បន្ថែមការផ្ទៀងផ្ទាត់ប្រភេទ Binds 
(clean_unbound, changeable_email, dead_bind) ព្រមទាំងរក្សាទុក listing 
snapshot នៃព័ត៌មានគណនីពេលរៀបចំលក់។ 
4.​ Media Upload Service: API បង្កើត Presigned URL ដើម្បីឱ្យ Client អាច Upload 
រូបភាពស្គ្រីនសតផ្ទាល់ទៅ Cloudflare R2 / S3 Storage។ 
ជំហានទី ៥៖ សេវាបញ្ជាទិញ និងការពារទិញជាន់គ្នា (Order & Concurrency Lock 
Module) 
1.​ Checkout Endpoint (POST /api/v1/orders/checkout): 
○​ ទទួលសំណើបញ្ជាទិញ និងពិនិត្យមើលភាពទំនេរនៃ Account មុនបង្កើតការកុម្ម៉ង់។ 
2.​ Distributed Locking (Redis Redlock): 
○​ ពេល Buyer ចុច Checkout ត្រូវ Acquire Lock លើ Key: 
lock:account:{account_id} រយៈពេល 15 នាទី (900s)។ 
○​ ប្រសិនបើ Account កំពុង Lock ត្រូវបដិសេធសំណើដោយផ្ញើ 409 Conflict (ការពារ Race 
Condition / Double-spending)។ 
3.​ Order State Machine: 
○​ ផ្លាស់ប្តូរ Status គណនីទៅជា reserved និងកំណត់ reserved_until = NOW() + 
15mins។ 
○​ កំណត់ Cron Job / Redis Keyspace Notification auto-release worker ដើម្បីដោះលែង 
Account (available) វិញភ្លាមៗ ពេលហួសពេលវេលាកំណត់ reserved_until បើ 
Buyer មិនបង់ប្រាាក់។

1.​ Dynamic KHQR Generator: ហៅ Bakong API ឬ generate KHQR string បញ្ចូល Amount

○​ ផ្ទៀងផ្ទាត់ HMAC-SHA256 Signature ពី Payment Gateway។ 
○​ ពិនិត្យភាពត្រឹមត្រូវនៃចំនួនទឹកប្រាាក់ (Amount Comparison)។

1.​ Ledger Accounting Service: 
○​ ករណី B2C (Platform Owned): ចំណូលកត់ត្រាាចូល Platform Treasury ផ្ទាល់។

wallets.balance ក្រោយចប់ពេល Dispute Window។ 
3.​ Withdrawal Management: API សម្រាាប់ Seller ស្នើសុំដកប្រាាក់ និង API សម្រាាប់ Admin ចុច

2.​ ករណីទី២ (C2C / Marketplace with Commission): អ្នកប្រើប្រាាស់ទូទៅដាក់លក់ Account 
ផ្ទាល់ខ្លួនលើ Platform។ ប្រព័ន្ធប្រើ Escrow Model ដោយប្រាាក់ពី Buyer ចូលមក Platform សិន។ 
ក្រោយពេល Buyer ផ្ទៀងផ្ទាត់ជោគជ័យ ប្រព័ន្ធកាត់កម្រៃជើងសារ (Platform Commission Fee ឧ. 
10%) ហើយបញ្ចូលលុយសុទ្ធ (90%) ទៅកាន់ Digital Wallet 
របស់អ្នកលក់ដើម្បីរង់ចាំការស្នើសុំដកប្រាាក់ (Withdrawal)។ 
២. គំនូសតាងលំហូរដំណើរការប្រព័ន្ធ (System Flowchart & 
Lifecycle) 
២.១ លំហូរទូទៅនៃការទិញលក់ និងការទូទាត់ (End-to-End Escrow Flow) 
1.​ Listing Stage: 
○​ Seller បង្កើត Listing គណនីហ្គេម ដាក់តម្លៃ រូបភាព និងបញ្ចូលព័ត៌មានសម្ងាត់ 
(Credentials) ដែលត្រូវ Encrypt ដោយស្វ័យប្រវត្តិ។ 
○​ សម្រាាប់ Platform-Owned Account ប្រព័ន្ធកំណត់ Flag is_platform_owned = 
true។ 
2.​ Order & Checkout Stage: 
○​ Buyer ជ្រើសរើសគណនី រួចចុច "ទិញឥឡូវនេះ"។ 
○​ ប្រព័ន្ធផ្លាស់ប្តូរ Status នៃ Account ទៅជា reserved រយៈពេល 15 នាទី ដើម្បីការពារ 
Race Condition (អ្នកទិញជាន់គ្នា)។ 
○​ ប្រព័ន្ធបង្កើត Order និងទាញយក KHQR / Payment Gateway។ 
3.​ Payment Verification: 

--- Page 2 ---
○​ Buyer ស្កេនបង់ប្រាាក់ ថវិកាចូលគណនី Bank របស់ Platform។ 
○​ Payment Gateway ផ្ញើ Webhook មកបញ្ជាក់ការទូទាត់។ Order status ប្រែជា 
completed (ឬ processing)។ 
4.​ Account Delivery: 
○​ ប្រសិនបើជា instant: ប្រព័ន្ធបង្ហាញ Credential (Decrypt) ជូន Buyer ភ្លាមៗក្នុងផ្ទាំង 
Order Detail។ 
○​ ប្រសិនបើជា manual: Buyer និង Seller ធ្វើការទាក់ទងគ្នាតាម Chat System 
ក្នុងវេបសាយ ដើម្បីផ្ទេរ Email/Password និងផ្ទៀងផ្ទាត់ OTP។ 
5.​ Settlement & Fund Allocation: 
○​ ប្រសិនបើ B2C: ចំណូលរត់ចូល Platform ទាំងស្រុង។ Order បញ្ចប់ដោយជោគជ័យ។ 
○​ ប្រសិនបើ C2C: 
■​ ប្រាាក់ត្រូវបានកាត់ Platform Commission (ឧ. 10%)។ 
■​ ប្រាាក់នៅសល់ 90% ត្រូវបញ្ចូលទៅក្នុង wallets របស់អ្នកលក់ និងកត់ត្រាាក្នុង 
wallet_transactions។ 
6.​ Withdrawal (ការដកប្រាក់របស់អ្នកលក់): 
○​ Seller ស្នើសុំដកប្រាាក់តាម withdrawal_requests (ABA, Wing, ACLEDA)។ 
○​ Admin ពិនិត្យ និងអនុម័ត (Approved) រួចផ្ទេរប្រាាក់ជូន Seller។
